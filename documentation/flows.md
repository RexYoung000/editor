# Forge 关键运行流程

本文只记录会跨越权限、数据完整性、外部系统或发布副作用的流程。普通画布编辑细节不在此重复。

## 打开、编辑与保存课程

| 项目 | 内容 |
| --- | --- |
| Actor | 老师或开发验收人员 |
| 前置条件 | Electron 已连接可用 Vite 地址；用户主动选择课程文件或新建目录 |
| 成功结果 | 最新课程 JSON 和实际使用资源写回当前活动课程目录 |
| 主要副作用 | 本机文件写入、无引用图片清理、活动路径与资源缓存更新 |

1. React 通过 preload 请求 Electron 文件选择或目录创建。
2. Electron 主进程解析真实路径并校验课程 ID、目标目录、覆盖关系和符号链接边界。
3. 课程进入 `editorStore.ts`，它是编辑期间唯一的课程状态源；Laya 对象只负责显示和高频反馈。
4. 属性编辑先写 store，再按一次编辑会话形成历史；保存前先提交未结束的属性事务。
5. 课程变化 15 秒后自动保存，`Ctrl/Cmd+S` 或文件菜单立即写回同一路径。
6. 另存为先在目标父目录完成临时复制、校验、备份切换和恢复标记，再把编辑器活动路径切到新副本。

必须拒绝：没有 Electron 文件权限、无效课程结构、目标等于源目录、双向目录嵌套、越界符号链接、普通非空目录覆盖、未确认的同名有效课程替换。目标已写成但 UI 切换失败时必须告诉老师副本位置，不能把已保存结果误报为丢失。

## 资源库检索与导入

| 项目 | 内容 |
| --- | --- |
| Actor | 老师；待评审 Agent 只能使用受控 MCP 工具 |
| 前置条件 | Vite 机器已同步正确素材快照；课程目录已登记 |
| 成功结果 | 选定素材复制进当前课程目录，课程只引用自己的副本 |
| 信任跨越 | Electron 页面 -> Vite 资源 API -> Electron 本机课程目录 |

1. 页面通过 `/api/library/*` 查询 Vite 机器上的 `public/builtin/library/`。
2. 服务端对相对路径、类型和目录根执行校验，不接受父目录跳转、绝对路径或 UNC。
3. 用户选定资源后，Electron 下载并复制到当前课程 `images/library/` 或对应动画/声音目录。
4. 课程 JSON 保存相对资源引用，不保存资源服务器路径或老师电脑绝对路径。

必须拒绝：路径越界、不支持的扩展名、未登记课程目录、资源快照缺失或 hash/大小校验失败。资源库没有登录保护，因此只能放在受控网络。

## 真实预览

| 项目 | 内容 |
| --- | --- |
| Actor | 老师或开发验收人员 |
| 前置条件 | 课程已保存；Electron 本机编译工具和 Vite preview API 可用 |
| 成功结果 | GameLoader 打开与当前课程内容对应的可运行预览 |
| 主要副作用 | 本机生成 `project/`、`esBuild/`；上传编译 ZIP；替换服务器预览目录 |

1. 工具栏先保存课程并执行结构、动作关系和资源校验。
2. `exportProject()` 根据课型生成 Laya 工程，下载模板 ZIP 和实际引用的 runtime 资源。
3. Electron `compileBuild` 调用 Laya 编译与 esbuild，生成可运行目录。
4. Electron 打 ZIP 并上传到 `/api/upload-compiled-zip`；Vite 先验证全部 ZIP 条目，再原子替换 `preview-server/lessons/<projName>/`。
5. 浏览器打开 GameLoader，按课型后缀和预习映射加载课件。

必须拒绝：课程关系失效、资源缺失、路径越界、压缩包结构不合法、300MB 上限、编译失败或上传失败。预览成功只证明当前预览，不代表老师已审核、SVN 已提交或正式发布。

## 老师课件发布

| 项目 | 内容 |
| --- | --- |
| Actor | 老师；最终结果依赖公司 SVN 和打包机 |
| 前置条件 | 对每个实际工程完成最新真实预览；老师在发布窗口亲自确认；已选择有效本地 SVN 文件夹 |
| 成功结果 | SVN commit 已核验，`integrationRequest` 已发送；只有收到打包机“全部完成”才显示发布成功 |
| 主要副作用 | 生成工程、整理本地 SVN 受管范围、打开 TortoiseSVN、远程提交、通知打包机 |

1. Electron 计算课程文本和完整工程目录的稳定 SHA-256；localhost 与局域网 HTTP 必须得到同一结果。
2. 老师确认预习/正课或对应课型工程，确认记录写入 Electron 用户目录，不进入课程 JSON。
3. Vite `/api/publish-config` 返回课型 SVN 基础地址；老师填写相对业务目录并主动选择本地 SVN 文件夹。
4. Electron 从本地 SVN 元数据读取真实 URL，判断原地发布或同步发布，并阻止目录重叠、身份冲突和待处理内容覆盖。
5. 内置 SVN CLI 只执行本地 `info/status/add/delete/revert`；远程 commit 必须由老师在 TortoiseSVN 窗口确认。
6. TortoiseSVN 关闭后，Electron 重新读取实际 revision、工程 URL、身份文件和工作区状态。
7. 核验通过后才发送打包机请求。通知失败时只保存待重试通知，不重复提交 SVN。

必须拒绝：确认指纹失效、无 TortoiseSVN、SVN URL 不匹配、路径重叠、身份冲突、本地受管内容未提交、提交后 revision/URL 不一致。工程生成、SVN 提交、通知发送和打包完成是四个不同状态。

## 产品版本发布与内部部署

| 项目 | 内容 |
| --- | --- |
| Actor | 仓库维护者、发布负责人、部署负责人 |
| 前置条件 | 独立版本 Issue/PR；自动检查和风险相关人工验收完成；回退版本和素材快照明确 |
| 成功结果 | 正式 Tag/Release、Windows 安装包、公司服务和老师端版本一致并有部署记录 |

1. 版本 PR 更新版本号、README 和发布记录，不在普通功能 PR 中顺手升级版本。
2. 合并后创建不可移动的 `vX.Y.Z` Tag 和 GitHub Release。
3. Windows workflow 检出明确 Tag 构建 NSIS，并把安装包上传到 Release。
4. 部署前备份 `public/builtin/library/`、`public/uploads/`、`preview-server/lessons/` 和本机配置。
5. 公司台式机切换明确 Tag，安装冻结依赖并运行 `pnpm dev`；不跟随 `main`。
6. 完成局域网、Electron、本地课程、资源库、预览和发布冒烟，再小范围交付老师。

必须拒绝：目标不是正式 Release、安装包/素材/回退点不完整、部署目录有来源不明的跟踪修改或本机数据未备份。Tag、构建和 SHA-256 都不能替代 Windows 安装、升级和真实业务验收。

## 待评审 Agent 作业制作

该流程只存在于本机 `feat/161-agent-homework-mcp`，不是 v1.5.1 能力。

1. Agent 读取 Forge MCP manifest、能力目录、兼容性和工具 guidance。
2. 老师确认合法且以 `_hw` 结尾的草稿 ID；MCP 只打开 Agent 自己创建的草稿。
3. 老师每轮要求对应一个事务；renderer 工作副本通过语义工具修改，提交时一次写回 Zustand 并保存检查点。
4. 素材先搜索 Forge 资源库；老师明确提供的图片或 PDF 裁图才可导入当前草稿。
5. 提交后执行草稿校验、截图和真实预览。Agent 推导答案保持 `answerConfirmed=false`，直到老师明确确认。
6. 老师仍通过现有 Forge 发布窗口审核和发布；MCP 不提供确认、SVN、打包或部署工具。

必须拒绝：旧 Skill、能力修订变化、第二个 Agent 同时写同一草稿、老师手动修改后的旧租约、任意课程 JSON、未授权文件路径、未确认答案的可发布结论。
