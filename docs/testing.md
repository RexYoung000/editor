# 测试与验收

forge 同时包含纯逻辑、React 界面、Laya 画布、Electron 本地文件和远程预览链路。单一测试手段不能覆盖全部风险，因此 PR 需要按改动范围组合自动检查和人工验收。

## 合并检查

所有 PR 至少执行：

```bash
pnpm lint
pnpm test
pnpm build
```

GitHub Actions 会对进入 `main` 的 PR 自动执行这三项检查。失败时不能通过修改测试、吞掉错误或降低约束绕过。

当前私有仓库使用 GitHub Free，Actions 可以运行，但 GitHub 暂时不能把检查设为 Branch Protection 的必需状态。升级 GitHub Pro 前，由评审者确认检查通过后再执行 Squash Merge；技术门禁配置跟踪见 [Issue #4](https://github.com/RexYoung000/editor/issues/4)。

## 四层验证职责

涉及交互设计时，根据不确定性和改动范围组合以下四层验证。它们解决的问题不同，不能互相替代：

| 验证层 | 主要用途 | 不负责验证 |
| --- | --- | --- |
| 对话内交互 Demo | 在实装前即时体验拖拽、吸附、动画、空间布局、连续数值、复杂状态切换，以及信息层级和视觉反馈 | 项目代码集成、Laya/Electron 边界、真实性能、本地文件和导出结果 |
| 浏览器真实页面 | 验证 React 页面、样式、响应式布局、浏览器事件和可访问的异常状态 | Electron IPC、桌面窗口行为和仅在 Laya 运行时成立的结果 |
| Electron 真实环境 | 验证 Laya 画布、桌面交互、本地文件、远程连接、预览导出和完整集成体验 | 不能替代可重复运行的逻辑回归保护 |
| 自动测试与构建 | 稳定保护纯逻辑、数据兼容、边界条件、历史事务、类型和构建结果 | 真实手感、视觉密度、动画节奏和桌面环境差异 |

存在实质交互不确定性时，设计预验收流程为：

1. 先对齐要解决的用户问题和本次范围。
2. 制作只覆盖关键判断的最小可操作 Demo，不复制完整产品。
3. 由 Rex 即时体验并确认参数、状态、交互规则和视觉反馈。
4. 将确认结果写回对应需求或设计文档，再开始项目实装。
5. 实装后继续执行自动检查，并按改动范围完成浏览器或 Electron 真实验收。

小型修复、规则明确的界面调整和无需体验判断的任务不强制制作 Demo。Demo 文件不进入产品源码或正式交付物；它用于提前收敛设计理解，不能替代最终集成验收。Issue #15 的 Axure 式动态距离提示是首次应用：先通过可拖拽 Demo 确认“两元素实时测距 + 三元素等距增强”，再回写设计文档并修改真实画布。Issue #52 通过完整图层面板拖拽 Demo 进一步确认“自由放置为主、弱磁吸为辅”、拖动与浮动透明度、取消拖动和窗口约束，再进入项目实装。

## 现有自动测试

`pnpm test` 通过 `scripts/run-unit-tests.mjs` 编译并运行 `tests/*.test.ts`。当前覆盖重点包括：

| 范围 | 主要验证 |
| --- | --- |
| 画布选择与命中 | 旋转命中、框选、父子选择、容器穿透 |
| 画布变换 | 多选移动、缩放、旋转、拖动复制和历史记录 |
| 图层显隐与锁定 | 自身状态、父级多层继承、父级解除后的子级恢复、锁定选择与变换限制、批量操作和单条历史 |
| 编辑器图层组 | 显式组与旧 `groupId` 选择边界、整行点击热区、成员独立框选/变换/删除、组级显隐/锁定批量操作、组外拖放、同运行父级约束、循环保护、组 ID 重建、复制粘贴、嵌套清理和单条历史 |
| 画布视口 | 缩放、平移、适应画布和可见边界 |
| 容器几何 | 越界判断、移回容器和扩展容器 |
| 内部页面 | 增删复制、页面分组兼容、插入排序、动作关系、跨关卡移动、弹窗编辑态底板与遮罩合成和编译 |
| 事件与 SDK 判定 | 触发元素与目标分离、兼容目标过滤、结果分支、失效引用、历史事件兼容和导出代码 |
| 图层面板布局 | 持久化状态归一化、自由浮动边界约束、尺寸上下限、弱磁吸命中和恢复默认 |
| 文本工具 | 创建后自动聚焦且定位在可见画布中央；空文本退出取消创建；原生光标、局部选区、中文输入法、双击定位、`Cmd/Ctrl+Enter`/`Esc` 退出；选中态拖动移动而编辑态拖动不移动；三种尺寸模式的手柄数量与自动高度；固定宽高溢出橙色提示；蓝白高对比辅助框在深浅背景、旋转和透明度下可见；一次编辑会话一次历史；画布、预览和导出排版一致 |
| 导出结果 | 正常课、作业、专题测评、预习、复习课和内部页面的场景、代码、配置与资源路径，以及正式与预习共享场景规则的一致性 |
| 模板与资源 | 自定义模板格式、资源扫描和 ID 重建 |
| 资源库 | 快捷标签、目录聚合、模糊搜索和系列识别 |
| 预览路由 | 正课与预习课程标识映射到共享上传目录，忽略 GameLoader 缓存参数，并保护普通课程名和真实缺失路径 |

新增纯逻辑或修复可复现缺陷时，应优先补单元测试。测试名称使用用户可理解的行为描述，不只描述内部函数。

## 构建检查

`pnpm build` 执行：

1. `tsc -b`：检查 TypeScript 类型和工程引用。
2. `vite build`：验证前端可以生成静态构建产物。

构建通过不代表 Electron、本地文件 API 或远程预览可用。

## lint 检查

`pnpm lint` 对 TypeScript、React Hooks、React Fast Refresh 和项目约定执行全量静态检查，并作为 CI 合并检查。

每个 PR 必须遵守：

- lint 零错误。
- 不关闭规则或扩大忽略范围来规避问题。
- 不用 `any`、不安全断言或吞掉异常替代真实类型设计。
- 类型治理不得顺手改变无关产品行为。

## 人工验收矩阵

| 改动范围 | 必须验收 |
| --- | --- |
| 普通 React 界面 | 浏览器关键路径、空状态、异常状态和不同窗口尺寸 |
| 图层面板布局 | 浏览器验证完整面板拖拽、任意位置自由放置、弱磁吸、三种停靠、各模式尺寸调整、收起、`Esc` 取消、恢复默认和窄窗口约束；长列表超出可视高度时，浮动、左侧、右侧和底部停靠模式均可在内容区独立上下滚动，标题栏不随内容滚动且拖拽排序仍可用；图层面板移动到全局弹窗区域时，弹窗遮罩和内容始终覆盖面板并阻断其操作；验证实际外层标题栏始终提供创建空图层组入口，未选择图层时也可点击；Electron 验证切换关卡与专注工作区、重启恢复布局、真实画布空间变化且始终只有一个面板 |
| 图层显隐与锁定 | Electron 验证图层行眼睛/锁定控件、父级隐藏/锁定对子级的继承来源、父级恢复后子级自身状态保持、锁定对象可选中查看但无变换手柄且不能拖动，属性面板编辑区域整体置灰，以及普通页与内部页面共用面板 |
| 编辑器图层组 | Electron 验证无需预选图层即可创建空组，再通过拖拽或组内移入整理成员；验证空组和有成员的组都可选中并同步高亮成员，点击成员行名称/类型/留白都能切换，单击组内成员只选该成员，单击组外元素一次即可切换；组右侧验证隐藏/显示组成员、锁定/解锁组成员，包含嵌套组且每次只写一条历史；成员可独立移动/缩放/旋转/删除，框选只包含实际命中成员；验证成员拖到普通层级会解除组归属且一步撤销可恢复，拖入其他组只更新一次归属；重命名/排序/解散/删除在右侧属性面板执行；同时验证旧 `groupId` 仍整组联动、图层组与运行容器视觉区分、展开状态、撤销恢复，以及预览和导出结构不变 |
| 点击触发 SDK 判定 | 浏览器验证普通按钮、图片、文本均可添加判定事件，目标只显示当前页兼容题型，独立输入格可直接填写正确答案，切换目标后答案摘要与正确/错误/未完成分支同步；Electron 依次预览独立输入格、填空、选择、拖拽和连线目标，验证正确、错误、未完成的真实结果与目标删除后的失效提示，并回归历史 ConfirmButton 快捷题型 |
| 选择题配置与交互 | 浏览器验证容器内选项增删改名、稳定答案引用、自动单选/多选推导、重复答案过滤和发布校验；Electron 验证文字点击穿透、单选替换与取消、多选自由勾选、通常/按压/选中/正确/错误状态替换、错误后重选、正确后锁定，以及正课确认按钮和线上作业“修改 / 完成 / 跳过”流程；真实导出验证正课、预习、作业和专题测评一致 |
| 专注工作区页面管理 | 浏览器验证统一列表、分组、搜索筛选和收起状态；Electron 验证拖拽命中、占位动效、自动滚动、快捷新增、撤销与保存重开 |
| 内部页面工作台入口 | 浏览器验证常显“进入编辑”、悬停快捷按钮、文字化更多操作和窄侧栏容纳；Electron 验证工作台画布只读、点击提示、按钮/双击/Enter 进入、返回后恢复只读，并确认普通小关卡仍可直接编辑 |
| 弹窗编辑与预览 | Electron 验证主界面底板、遮罩、弹窗内容三层顺序；编辑态依次检查遮罩 0%、55%、100% 和颜色切换，并确认遮罩不可选中且不进入图层列表；正课与预习真实预览确认遮罩颜色、透明度和底板拦截与编辑态一致 |
| Laya 画布与组件 | Electron 中的添加、选择、变换、撤销和预览表现 |
| 本地文件与模板 | Electron 打开真实课程、保存、重启后读取和资源去重 |
| 远程模式 | Vite 与 Electron 分别运行，确认没有发送本机绝对路径 |
| 预览与导出 | 生成课件、上传预览、GameLoader 打开和关键交互；资源进度达到 100% 后启动层应退出并显示首屏，不能停留在“正在启动” |
| 内置资源 | 编辑器显示、导出路径和课件包资源存在性 |
| Electron 打包 | Windows 安装包启动、连接服务器和相关 IPC |

PR 只需要执行与风险相关的项目，但必须说明未覆盖项。

## PR 验收记录

PR 中应写清楚：

- 自动执行了哪些命令及结果。
- 人工验收入口和操作路径。
- 应看到的结果及实际结果。
- 未覆盖的环境或场景。
- 已知限制、偏差或后续 Issue。
- 视觉改动的截图或录屏。

不要只写“测试通过”。评审者应在不阅读代码的情况下判断改动是否达到 Issue 目标。

## 发布前回归

版本发布除 PR 门禁外，还需要：

1. 对照版本 Issue 回归所有用户可感知变化。
2. 在真实 Electron 环境打开、编辑和保存课程。
3. 验证至少一种正常课件的预览与发布。
4. 验证本版本涉及的课程类型和资源类型。
5. 执行 `pnpm electron:build` 并检查安装包启动。
6. 在 Windows 上实际安装 NSIS 安装包，验证首次安装、覆盖安装、服务器连接和本版本涉及的关键 IPC。
7. 使用与正式部署等价的 Vite 服务完成局域网 Electron 连接、资源库、真实课程保存、预览和发布冒烟检查。
8. 核对编辑器显示版本、安装包版本、目标 Tag 和 Release 版本一致。
9. 记录未解决问题、未覆盖环境、素材快照和回退方式。

最终发布由项目负责人执行。

完整的发板、公司台式机部署、老师端交付和回退流程见 [正式发板与内部部署](./internal-deployment.md)。
