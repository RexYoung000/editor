# 第二阶段：豌豆思维组件归类与信息管理

> 更新日期：2026-07-16
> 用途：记录组件分类方向、S1-S9 组织方式和后续 issue 拆解依据。

## 背景问题

当前编辑器已经接入了大量组件，但组件分类仍然带有历史业务线痕迹。例如当前工具栏中存在“豌豆口才”等分类，而当前版本主要服务豌豆思维这一条业务线。

当老师只需要制作豌豆思维课件时，过多无关业务线表达会增加查找成本。后续如果继续加入资源和组件，而不先整理分类，组件区会越来越难用。

## 目标效果

老师打开组件区后，应该只看到当前业务线真正需要的内容。

目标是：

- 组件体系收敛到豌豆思维。
- 支持按 S1 到 S9 的年级或阶段维度组织组件。
- 老师可以根据当前课件阶段快速找到合适组件。
- 组件字段保留现有可用能力，后续根据真实需求逐步增删。

## 当前项目现状

当前组件主要集中在 `elementMeta` 中维护。工具栏分类从 metadata 读取，目前已有分类包括“常用组件”和“豌豆口才”。

当前已有能力：

- 组件可以通过 metadata 定义名称、分类、默认属性和属性面板字段。
- 属性面板可以根据组件字段动态渲染。
- 文件字段已经支持本地文件和资源库文件。
- 自定义组件和组合组件已经有一定基础。

当前缺口：

- 分类还没有按豌豆思维业务线收敛。
- 没有 S1-S9 的筛选或组织方式。
- 组件适用年级、适用场景、推荐用法没有统一记录。
- 组件字段虽然可用，但缺少面向老师的整理口径。

## 方案方向

第二阶段先做组件信息整理，再做界面改造。

推荐方向：

- 只保留豌豆思维相关组件入口。
- 图片、文本、按钮、容器等基础组件统一标记为全阶段，筛选任意 S1-S9 时始终可见。
- 业务组件按 S1-S9 进行信息标注，并允许同时属于多个阶段。
- 无法从当前项目和业务资料确认归属的组件标记为“待确认”，不擅自隐藏或下线。
- 先不删除底层能力，优先在入口和分类上做收敛。
- 字段增删不提前大改，等老师真实使用反馈后再调整。

组件信息建议至少包含：

- 组件名称。
- 组件用途。
- 适用阶段：S1-S9。
- 推荐使用场景。
- 是否为高频组件。
- 是否需要模板配合使用。
- 是否暂时隐藏。

## 不做什么

第二阶段暂不处理：

- 资源库分离。
- 大规模重写组件底层实现。
- 一次性删除所有历史组件。
- 设计完整的跨业务线组件市场。
- 给每个组件做复杂教学说明。

## 验收标准

第二阶段完成的标准：

- 老师进入组件区后，不会被无关业务线分类干扰。
- 可以按 S1-S9 找到对应组件。
- 高频组件能被更快找到。
- 每个显示出来的组件都有明确用途。
- 后续新增组件时，有清楚的归类规则。
