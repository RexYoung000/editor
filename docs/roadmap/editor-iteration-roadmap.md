# 编辑器阶段性迭代路线

> 更新日期：2026-07-26
> 用途：作为后续拆 issue、排优先级、验收阶段成果的主路线文档。

## 背景问题

当前编辑器已经具备课件编辑、组件添加、元素层级、资源导入、预览导出等基础能力，但老师在真实制作课件时，主要困难不在“能不能做”，而在“做起来是否顺手”。

现阶段最明显的问题是：一个小关卡里经常包含主界面、二级弹窗、同级切换页面、按钮触发关系等多层内容，但这些内容现在都堆在同一个画布和同一个元素列表里。老师需要频繁通过隐藏、层级、父子容器、元素命名来管理逻辑，操作成本高，出错后也很难快速定位。

因此，后续迭代优先围绕老师的编辑体验展开，而不是优先扩展底层能力或资源服务器。

## 总目标

让老师可以更清楚地理解课件结构，更快地定位和编辑内容，更低成本地复用已有组件和模板。

阶段目标按优先级分为三个可完成的里程碑，并保留一个长期需求池：

1. 解决编辑器中阻塞制作效率的关键交互痛点。
2. 整理豌豆思维业务线下的组件分类和信息管理方式。
3. 建立组合预设模板，让老师可以从常用结构快速开始。

持续出现的体验优化需求进入长期需求池，在完成对齐并排入具体里程碑后再开放领取。

资源库检索改造 [#73](https://github.com/RexYoung000/editor/issues/73) 保留为独立任务，不再绑定已经发布的版本；正式实施前仍需确认资源快照、标签映射和视觉资料。更大范围的资源库分离继续作为后备方案保留。

## 阶段一：交互与层级管理

目标：解决小关卡内部多界面、多弹窗、多层级内容难管理的问题。

**当前状态：三套交互原型对比、专注工作区、画布基础交互、智能吸附、图层命名、显隐锁定、图层组和 #17 图层树折叠搜索与选择同步均已完成；#20 基础选择集属性已实现并进入评审，合入后进入 #13 端到端回归。设计与实施以 [画布与图层基础交互整体优化设计](./canvas-layer-interaction-design.md) 和 [第一阶段：专注工作区正式交互设计](./phase-1-focus-workspace-design.md) 为准。**

重点方向：

- 把小关卡理解为一个“文件夹”，内部可以管理主界面、二级界面、弹窗和同级页面。
- 工作台继续管理大关卡和小关卡；进入小关卡后使用专注工作区管理内部页面。
- 左侧用横向缩略图页面树组织主界面、内容页和弹窗，当前页面展开现有元素树。
- 页面跳转、打开弹窗和关闭弹窗接入现有动作序列，在右侧属性栏统一配置。
- 支持页面创建、复制、删除、排序和跨兼容小关卡移动，并在操作前说明关系影响。
- 测试交互时锁定编辑控件，通过画布真实按钮验证运行链路。
- 统一首次拖动、多选移动/缩放/旋转、框选、吸附、历史和镜头导航，普通页面与内部页面不再有两套手感。
- 把元素列表升级为图层面板，采用“最上方图层位于视觉最上层”的顺序，并区分运行容器与编辑器图层文件夹。
- 阶段一完成图层顺序、名称、折叠搜索、显隐锁定、图层组和基础选择集属性；完整右键菜单与高级批量编辑进入长期需求池。

产出物：

- 三方案可点击原型与体验记录（已完成）。
- 专注工作区正式交互设计（已完成）。
- 画布与图层基础交互整体优化设计（已完成）。
- 画布与图层第一批基础交互、单元测试与真实画布验收（已完成）。
- 多选缩放旋转与拖动复制、自动测试和 Electron 真实画布验收（第二批已完成）。
- 智能吸附、图层命名、显隐锁定和图层组（已完成）。
- 图层树折叠搜索、基础选择集属性与阶段端到端回归（待完成）。

## 阶段二：组件归类与信息管理

目标：把组件体系收敛到当前业务线，让老师只看到和豌豆思维相关的内容。

**当前状态：#21 组件业务归属盘点已处于“可领取”，可以与阶段一主线并行；后续按 #22 元数据标准 → #23 入口收敛 → #24 S1-S9 筛选 → #25 高频入口推进。依赖未完成前不根据组件名称猜测业务归属。**

重点方向：

- 当前版本仅服务豌豆思维业务线。
- 去除或隐藏当前不需要的其他业务线表达，例如豌豆口才。
- 在豌豆思维逻辑下管理组件分类。
- 支持按 S1 到 S9 的年级维度组织组件信息。
- 图片、文本、按钮、容器等基础组件标记为全阶段，筛选 S1-S9 时始终可见。
- 业务组件可以同时属于多个阶段；无法确认归属时标记为“待确认”，不擅自隐藏。
- 组件字段暂时沿用现有字段体系，后续根据真实制作需求增删。

产出物：

- 组件分类文档。
- S1-S9 分类规则。
- 组件归属清单。
- 后续组件字段调整 issue。

## 阶段三：组合预设模板

目标：把高频课件结构沉淀成可复用模板，让老师可以一键添加后快速编辑。

重点方向：

- 组合常见题型和页面结构。
- 老师添加模板后，可以直接改图、改文本、增删按钮和调整交互。
- 模板优先服务真实高频场景，不追求一次性覆盖所有题型。
- 继续沿用现有自定义模板能力，避免重复造一套模板系统。
- Rex 提供真实模板效果后逐项确认；每个模板使用独立 Issue 和稳定模板 ID，不先虚构固定数量或未确认的题型清单。
- 纯版式模板可以在适用课件类型、资源和可编辑边界确认后实施；复杂题型、弹窗或 S1-S9 绑定仍需等待对应结构与组件信息成熟。

产出物：

- 模板规划文档。
- 首批模板清单。
- 每个模板的适用场景和验收标准。
- 模板制作与维护 issue。

## 长期需求池：后续优化需求

目标：在前三个阶段建立稳定体验基础后，持续处理使用过程中出现的新问题。

可能方向：

- 完整图层右键菜单。
- 高级批量编辑和同类型共同属性修改。
- 更清晰的事件与动作配置。
- 更细的老师使用反馈优化。

长期需求池不作为需要整体完成的阶段里程碑。后续需求先以“需求池：长期优化”标签进入 Project，完成范围、优先级和验收对齐后，再排入具体 Milestone 并转为“可领取”。

## 资源库分离后备方案

资源库分离暂不进入短期主线。原因是当前首要目标是验证和优化编辑体验，资源素材规模和协作方式还没有成为阻塞点。

保留该方案的原因：

- 如果大量资源继续进入项目工程，仓库会变重。
- 如果多个老师或开发者共享资源，独立资源服务会更合理。
- 如果资源更新频繁，代码仓库不适合作为资源库。

触发时机：

- 素材明显影响仓库体积或拉取速度。
- 需要多人共享同一套美术资源。
- S1-S9 组件分类依赖大量外部素材。
- 当前 `public/builtin/library` 不再适合承载资源。

## Issue 拆解原则

后续 issue 应按老师能感受到的变化来拆，不按代码文件拆。

阶段与模块使用不同维度管理：Milestone 表示阶段，中文模块标签表示产品归属。一个 Issue 只设置一个主要模块；跨模块影响写入依赖和影响范围，避免筛选时重复统计。阶段 Milestone 已经承担阶段聚合，不额外建立不能独立领取和验收的阶段父 Issue。

每个 issue 至少包含：

- 为什么做。
- 老师会看到什么变化。
- 不包含什么。
- 如何验收。

示例标题：

- 支持在小关卡内快速切换弹窗界面。
- 支持查看按钮会打开哪个二级界面。
- 支持按 S1-S9 筛选豌豆思维组件。
- 支持一键添加常用练习题模板。

## 阶段依赖

- 阶段一优先级最高。只有小关卡内部结构管理清楚后，后续组件和模板才不会继续加重混乱。
- 阶段二依赖阶段一的基础体验，但可以在阶段一原型结论后并行做组件清单梳理。
- 阶段三的复杂交互模板依赖阶段一结构和阶段二组件信息；范围清楚、无复杂题型逻辑的独立版式模板可以在 Rex 提供真实效果和资源后逐项实施。
- #73 资源库检索改造在资源快照、标签映射和视觉资料确认后重新排期；更大范围的资源库分离仍依赖阶段二或阶段三的素材规模判断。
