# 资源库分离后备方案

> 更新日期：2026-07-14
> 用途：记录资源库分离的背景、暂缓原因、触发时机和未来方案方向。

## 背景问题

当前资源库实现读的是运行 Vite 服务那台机器上的 `public/builtin/library` 目录。维护者可以把素材放进这个目录，编辑器通过资源库按钮浏览和下载资源。

这种方式适合短期测试，但如果后续大量美术资源都放进项目工程并提交到代码仓库，会带来问题：

- 项目仓库越来越大。
- 拉取代码、切换分支、备份都会变慢。
- 素材更新和代码更新混在一起，不利于管理。
- 多人共享资源时，代码仓库不适合承担资源服务器职责。

## 当前决策

资源库分离暂不进入短期主线。

原因：

- 当前最重要的目标是优化老师编辑体验。
- 第一阶段还在验证小关卡内部交互管理方式。
- 组件分类和模板体系尚未稳定。
- 现阶段素材规模还不是最阻塞的问题。

因此，资源库分离先作为后备方案记录，不进入第一阶段实施范围。

## 当前项目现状

当前已有资源库能力：

- `/api/library/list` 列出资源库目录。
- `/api/library/file-info` 获取文件 hash 和大小。
- `/api/library/spine-files` 获取 Spine 工程文件清单。
- `/builtin/library/...` 直接访问资源文件。
- 选中资源后，会复制到当前课件本地目录。

重要特点：

- 资源一旦被选中，会进入课件目录。
- 已经进入课件目录的资源，不依赖原资源库路径。
- 资源库路径改名后，已经使用的课件资源仍然可以继续显示。

## 当前可行的内网试用部署模型

当前版本可以采用“一台内网服务器，多台 Electron 客户端”的方式试用：

```text
内网服务器电脑
├── Forge 项目代码
├── public/builtin/library/ 资源库
└── pnpm dev（0.0.0.0:6688）
          │
          ├── 编辑器页面
          ├── 资源库浏览与下载接口
          ├── 课件预览上传接口
          └── GameLoader 预览资源
                    ↓ 内网访问
用户电脑
├── 安装 Forge Electron 客户端
├── 输入 http://服务器内网IP:6688
└── 在本机选择并保存各自的课件目录
```

部署顺序：

1. 在 Mac 上完成基础功能开发并推送到远程代码仓库。
2. 在承担内网服务的电脑上拉取 Forge 项目并安装依赖。
3. 把共享素材放到该服务器项目的 `public/builtin/library/`。
4. 在服务器电脑上运行 `pnpm dev`。
5. 确保服务器有稳定内网 IP，并允许其他电脑访问 6688 端口。
6. 其他用户安装 Electron 客户端，启动时填写服务器地址。
7. 用户在自己电脑上选择课件目录；选中的资源库文件会下载到该课件本地目录。

需要明确的边界：

- 服务器运行的是当前 Forge 的完整 Vite 服务，不是一个只提供素材的独立资源服务。
- 其他用户共享编辑器页面和资源库，但不共享本地课件目录；课件源文件仍保存在各自电脑。
- 普通浏览器可以打开编辑器页面，但缺少 Electron 提供的本地目录选择、文件写入、编译和打包能力，不能作为完整使用方式。
- `pnpm build` 只有静态页面，不包含资源库、上传和预览接口；当前必须运行 `pnpm dev`。
- 当前没有账号、权限和资源访问控制，只适合可信内网试用。
- 服务器停机或 6688 端口不可达时，客户端无法加载编辑器和资源库；已经下载到课件目录的素材仍然保留。

这个部署模型可以验证多人共享资源库和远程编辑器的可行性，但不应被视为最终生产部署方案。

## 资源库全局搜索

### 状态与目标

状态：2026-07-14 已实施，作为现有资源库浏览能力的增强。

目标：在保留现有目录标签浏览的基础上，增加接近 Everything 的即时文件名搜索，让用户不需要逐层进入目录即可定位资源。

### 第一版产品范围

- 搜索整个资源库，而不是只筛选当前目录。
- 递归覆盖 `public/builtin/library/` 下的所有受支持资源。
- 只匹配文件名；目录路径只用于结果展示和同名文件区分。
- 忽略英文大小写，支持中文、英文、数字和常见符号。
- 多个空格分隔的关键词使用 AND 匹配：每个关键词都出现在文件名中即可，顺序不限。
- 图片属性只返回图片，音频属性只返回音频，视频属性只返回视频。
- Spine 选择模式按 Spine 工程文件夹名称搜索，结果单位仍是完整 Spine 工程文件夹。
- 搜索结果使用现有缩略图网格，显示文件名和完整相对目录。
- 搜索栏沿用快捷组件的布局，并提供系列、颜色、语言精确筛选；筛选标签从资源路径与文件名中提取，不改变关键词只匹配文件名的规则。
- 清空搜索词与全部筛选时恢复现有三级标签和目录浏览。
- 选中搜索结果后继续复用现有下载、内容 hash 去重和课件本地落盘流程。

示例：

```text
搜索词：按钮 蓝色

可匹配：
- 蓝色确认按钮.png
- 口才_蓝色按钮_02.png

不匹配：
- 蓝色按钮/img_01.png
  原因：第一版只匹配文件名，不匹配目录名。
```

### 不在第一版范围

- 不做 AI 语义搜索。
- 不识别图片画面内容。
- 不建设独立标签和标签维护后台。
- 不搜索文件正文或资源元数据。
- 不做收藏、最近使用和搜索历史。
- 不复制 Everything 的操作系统级磁盘索引能力。

### 推荐实现方向

1. Vite 服务端为资源库建立轻量内存索引，记录文件名、相对路径、资源类型、大小和更新时间。
2. 新增 `GET /api/library/search`，接收关键词、资源类型和结果数量上限。
3. 搜索请求在服务端完成，客户端不递归拉取全部目录。
4. 关键词统一大小写并按空格拆分，执行无序 AND 包含匹配。
5. 默认限制返回数量，例如 200 条，避免一次渲染过多缩略图。
6. 资源目录变化后通过短周期缓存失效自动重建索引，采用跨平台稳定方案，不依赖不同系统行为不一致的文件监听。
7. 资源库弹窗顶部增加搜索框，输入后短防抖请求；清空后回到目录浏览。
8. 保留结果中的完整相对目录，解决同名素材无法区分的问题。

### 前置约束

搜索效果依赖文件名质量。资源仍需建立最低限度的命名规范，建议包含业务、用途、状态和序号，例如：

```text
口才_选择题背景_蓝色_01.png
通用_确认按钮_按下态_02.png
```

如果大量资源继续使用 `img_01.png`、`pic2.png` 等名称，仅做文件名搜索无法解决定位问题。

### 搜索功能验收标准

- 输入一个关键词后，可以跨目录找到匹配文件名的资源。
- 输入多个关键词后，只返回同时包含全部关键词的结果，关键词顺序不影响结果。
- 图片、音频、视频和 Spine 模式不会返回不可选类型。
- 同名结果能通过目录路径明确区分。
- 清空搜索词和全部筛选后恢复原有目录标签浏览，原流程不受影响。
- 新增、删除或替换资源后，索引可在约定时间内自动更新，不要求重启 Forge 服务。
- 选中搜索结果后，资源仍能正确下载到本地课件目录并参与导出。
- 资源库规模达到实际使用量时，搜索交互仍保持即时感，不出现明显输入阻塞。

## 未来推荐方向

未来更合理的方向是把大资源从代码仓库中分离出来。

可以考虑三种方式：

### 方案 A：稳定服务器本地目录

在一台稳定机器上放置资源目录，并运行资源服务。

特点：

- 实现成本低。
- 适合公司内网。
- 可以由 Windows、Mac 或 Linux 承担，不必须是 Windows。

### 方案 B：从 SVN 同步到资源服务器

资源仍由 SVN 管理，但资源服务器定时或手动同步一份到本地目录，对编辑器提供 HTTP 访问。

特点：

- 保留公司现有资源管理方式。
- 编辑器不直接依赖 SVN。
- 可以避免老师端实时访问 SVN。

### 方案 C：独立资源服务

单独做资源目录接口、缩略图、下载、权限和缓存。

特点：

- 长期最清晰。
- 成本最高。
- 适合资源规模大、多人协作多、更新频繁的阶段。

## 触发时机

满足以下任一情况时，应重新启动资源库分离方案：

- `public/builtin/library` 中素材明显变大。
- 项目仓库拉取速度明显受影响。
- 资源需要多人共享和统一维护。
- S1-S9 组件分类依赖大量素材。
- 模板体系需要大量图片、音频、视频或 Spine 动画。
- 老师或开发者需要访问同一套远程素材。

## 不做什么

当前阶段暂不处理：

- 不改资源库接口。
- 不新增远程资源服务器配置。
- 不迁移现有资源目录。
- 不把资源服务器作为第一阶段交互优化的前置条件。
- 不要求必须准备一台 Windows 电脑作为资源服务器。

## 可拆 issue

后续需要启动时，可以拆这些 issue：

1. 调研当前资源体积和仓库增长速度。
2. 确定资源服务器承载方式。
3. 设计远程资源库地址配置。
4. 支持从远程资源服务读取目录。
5. 支持从远程资源服务下载文件到课件目录。
6. 支持资源服务错误提示和重试。
7. 验证已下载资源不依赖远程资源库。

## 验收标准

资源库分离完成的标准：

- 大体积素材不需要进入代码仓库。
- 编辑器可以浏览远程资源目录。
- 选中资源后，资源会进入当前课件目录。
- 远程资源库断开后，已使用资源不受影响。
- 资源库维护方式清楚，不依赖老师理解技术细节。
