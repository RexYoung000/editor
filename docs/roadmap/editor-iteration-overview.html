让老师更顺手地制作豌豆思维课件

当前编辑器已经具备基础制作能力，下一阶段重点不是继续堆功能，而是把复杂小关卡里的层级、弹窗、组件和模板整理成老师能理解、能快速操作的工作流。

当前主线：编辑体验 第一阶段：先做原型对比 资源库分离：暂缓进入后备
小关卡不是一张平面图 目标结构
主界面 题干、核心操作区、主要按钮
弹窗 A 由按钮 A 打开，支持快速定位和关闭链路
弹窗 B 独立编辑，不再靠手动隐藏一堆元素
同级页面 用于题内切换，仍属于当前小关卡
为什么要先做交互体验

现在的主要问题不是不能做，而是做起来太绕。

老师面对的是课件结构和教学内容，不应该被层级、父容器、显隐状态和元素命名拖住。

复杂内容堆在同一画布

主界面、弹窗、二级界面、按钮状态都混在一起，内容越多越难判断当前正在编辑哪一层。

元素列表只表达层级

老师能看到父子关系，但看不出“哪个按钮打开哪个弹窗”“哪个区域属于哪个内部界面”。

后续组件和模板会放大混乱

如果不先整理小关卡内部结构，组件分类和模板越丰富，老师越容易迷失。

四阶段路线

先把编辑结构理顺，再做组件、模板和后续优化。

阶段之间有明确依赖：第一阶段解决操作混乱，第二阶段收敛组件，第三阶段沉淀模板，第四阶段持续处理反馈。

PHASE 01

交互与层级管理

解决小关卡内部多界面、多弹窗、多层级内容难管理的问题。

  • 小关卡作为文件夹
  • 主界面、弹窗、二级界面可索引
  • 先做可点击原型对比
  • 暂不直接改正式导出逻辑
PHASE 02

组件归类与信息管理

把组件体系收敛到豌豆思维，让老师只看到当前业务线需要的内容。

  • 隐藏无关业务线表达
  • 按 S1-S9 组织组件
  • 建立高频组件清单
  • 字段后续按真实需求增删
PHASE 03

组合预设模板

把高频课件结构沉淀成模板，让老师一键添加后快速改图、改文字、改按钮。

  • 优先整理真实高频场景
  • 模板可继续编辑
  • 少量高质量模板先行
  • 和组件分类逐步联动
PHASE 04

后续优化需求

在前三阶段建立稳定体验基础后，持续处理真实使用反馈。

  • 右键菜单
  • 智能参考线
  • 批量操作
  • 事件动作配置优化
第一阶段重点

先验证“小关卡内部多界面”到底怎样管才顺手。

本阶段先做可点击原型，不直接改正式数据结构。验证清楚后，再拆正式实现 issue。

方案 A

小关卡内部界面节点

小关卡仍是预览和导出的基本单元，内部新增主界面、弹窗、二级界面等节点管理。

  • 更保护现有导出逻辑
  • 更贴近“小关卡是文件夹”的理解
  • 适合作为正式实现方向重点验证
方案 B

内部页面列表

把内部界面做成类似小页面的展开列表，让老师像管理页面一样管理弹窗和二级界面。

  • 视觉上接近现有页面列表
  • 上手可能更快
  • 需要避免和正式小关卡导出概念混淆

关键风险：不要提前混用 subPage

当前导出会把一个关卡下的多个小关卡导出为多个 subview。如果把弹窗和二级界面直接复用为现有小关卡，预览和导出可能把它们理解成课件流程步骤，而不是当前题内的界面状态。

原型验证路径

1
进入小关卡 看到主界面，以及当前小关卡内部有哪些弹窗和二级界面。
2
打开结构管理区 左侧栏向右展开，显示当前小关卡内部结构和链路。
3
切换到弹窗 A 画布聚焦弹窗内容，减少手动隐藏其他元素。
4
查看按钮链路 能看出按钮 A 打开弹窗 A，关闭按钮回到主界面。
5
形成正式方向 确定后再进入真实编辑器实现，不把原型验证和正式数据改造混在一起。
后续阶段

组件和模板要建立在清晰结构之上。

第二、三阶段不是不重要，而是要等第一阶段把编辑结构理顺后，才能发挥真正价值。

第二阶段：豌豆思维组件归类

把组件入口收敛到当前业务线，按 S1-S9 管理，让老师更快找到适合当前课件阶段的组件。

  • 梳理当前组件中哪些属于豌豆思维
  • 隐藏当前不需要展示给老师的其他业务线组件
  • 设计组件区的 S1-S9 筛选体验
  • 建立高频组件和待隐藏组件清单

第三阶段：组合预设模板

把高频页面结构和交互组合沉淀成模板，老师一键添加后直接改图、改文本、增删按钮。

  • 梳理老师最高频使用的 5 个课件结构
  • 定义首批组合预设模板清单
  • 制作单题讲解、练习题、二级弹窗模板
  • 验证模板是否方便继续编辑
资源库分离

先记录为后备方案，不进入当前短期主线。

当前短期重点是编辑体验。等素材规模、组件分类或模板体系真正需要时，再启动资源库分离。

触发条件 说明
项目仓库明显变重 大量素材进入 `public/builtin/library` 后，拉取代码和切换分支都会变慢。
多人共享同一套素材 代码仓库不适合承担长期资源服务器职责，需要独立维护资源目录。
S1-S9 分类依赖大量素材 当组件和模板强依赖大量图片、音频、视频、Spine 时，再做分离更合适。

未来方向

优先考虑稳定服务器目录，或从 SVN 同步到资源服务器。长期再考虑独立资源服务。

  • 编辑器浏览远程资源目录
  • 选中资源后进入课件本地目录
  • 远程断开后已用资源不受影响
Issue 编排方式

后续任务按老师能感受到的变化拆。

不按代码文件拆，不用技术名词当标题。每个 issue 都要说清为什么做、老师看到什么、不包含什么、怎么验收。

推荐 issue 标题

  • 支持在小关卡内快速切换弹窗界面
  • 支持查看按钮会打开哪个二级界面
  • 支持按 S1-S9 筛选豌豆思维组件
  • 支持一键添加常用练习题模板

第一阶段先拆原型

第一阶段正式实现任务要等原型对比结论出来后再拆。现在先验证老师完成“打开弹窗、编辑弹窗、返回主界面、查看链路”的路径是否更顺。
