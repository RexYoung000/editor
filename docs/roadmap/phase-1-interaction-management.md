# 第一阶段：小关卡内部交互与层级管理

> 更新日期：2026-07-08  
> 用途：记录第一阶段目标、原型验证方向、后续 issue 拆解依据。

## 背景问题

老师制作一个题目时，一个小关卡里往往不只是一个静态画面。它可能包含：

- 主界面。
- 一个或多个二级弹窗。
- 同级切换页面。
- 按钮打开某个界面的链路。
- 需要临时隐藏的辅助内容。
- 多层父子容器和交互组件。

当前这些内容全部堆在同一个画布和同一个元素列表中。老师为了编辑某个弹窗，需要不断隐藏其他元素、找父级、切换层级、判断哪个按钮对应哪个内容。随着元素增多，整个小关卡会变得很难理解，也很难排查问题。

## 目标效果

老师应该能把一个小关卡理解成一个“文件夹”。在这个文件夹里，老师可以清楚看到：

- 当前小关卡有哪些内部界面。
- 哪个是主界面。
- 哪些是弹窗或二级界面。
- 哪些按钮会打开哪些界面。
- 当前正在编辑的是哪一层内容。
- 如何快速返回主界面。

最终效果不是让老师学习更多层级概念，而是让复杂结构变得像整理文件夹一样直观。

## 当前项目现状

当前数据结构里，课件大致是：

- 关卡 `stage`
- 小关卡 `subPage`
- 元素 `elements`

现有导出逻辑会把同一个 `stage` 下的多个 `subPage` 导出为多个 `subview`。第一个通常是主视图，后续会被理解成这个关卡里的后续步骤或练习视图。

当前已有能力：

- 左侧上半区域管理关卡、小关卡和预习关卡。
- 左侧下半区域管理当前小关卡里的元素列表。
- 元素支持父子层级。
- 元素支持编辑器内隐藏。
- 部分组件已经具备内部翻页能力，例如 `PageTurnBox` 和 `ContainerBox`。
- 右侧属性面板可以配置父容器、事件和动作。

当前缺口：

- 没有“小关卡内部界面”的明确管理入口。
- 元素列表只能看到元素层级，不容易理解界面结构。
- 按钮和弹窗之间的链路不够直观。
- 编辑某个弹窗时，老师仍然需要手动处理大量显隐和定位。
- 没有针对复杂小关卡的快速索引。

## 方案方向

第一阶段不直接改正式数据结构，先做可点击原型对比。

需要对比两个方向：

### 方向 A：小关卡内部界面节点

小关卡仍然是当前预览和导出的基本单元。小关卡内部新增“界面节点”概念，用来管理主界面、弹窗、二级界面和同级页面。

特点：

- 更保护现有预览和导出逻辑。
- 更符合“小关卡是文件夹”的理解。
- 内部界面本质仍然属于当前小关卡。
- 适合先作为第一阶段正式实现方向。

需要验证：

- 老师是否能理解“主界面 / 弹窗 / 二级界面”的节点结构。
- 左侧栏向右展开是否足够清晰。
- 是否能明显减少手动隐藏元素的操作。

### 方向 B：内部界面做成类似小页面列表

在小关卡下展开多个内部页面，让老师像管理小页面一样管理弹窗和二级界面。

特点：

- 视觉上更接近现有页面列表。
- 老师可能更容易上手。
- 但如果直接复用现有 `subPage`，会影响导出对小关卡的理解。

需要验证：

- 是否会让老师误以为这些内部页面是正式课件流程步骤。
- 是否会和现有关卡、小关卡层级混淆。
- 如果后续实现，是否需要单独的数据结构，而不是直接复用 `subPage`。

## 可点击原型验证范围

第一版原型只验证弹窗和二级界面场景。

示例场景：

- 一个小关卡包含主界面。
- 主界面上有两个按钮。
- 按钮 A 打开弹窗 A。
- 按钮 B 打开弹窗 B。
- 弹窗内有关闭按钮。
- 老师可以在结构区快速切换主界面和弹窗。

原型必须展示：

- 左侧栏向右展开后的结构管理区。
- 当前小关卡内部界面列表。
- 当前编辑界面的聚焦状态。
- 按钮到弹窗的链路关系。
- 快速显示、隐藏、定位和返回主界面。

原型暂不验证：

- 真实导出。
- 真实课件运行。
- 完整事件系统。
- S1-S9 组件分类。
- 资源库。

## 小关卡导出边界风险

第一阶段需要特别注意：不要在没有验证清楚前，把弹窗和二级界面直接改造成现有 `subPage`。

原因：

- 当前 `subPage` 已参与导出。
- 多个 `subPage` 会被导出为 `subviews`。
- 弹窗和二级界面通常是当前题内部的状态，不一定是课件流程里的下一步。
- 如果混用概念，后续预览和导出可能出现理解偏差。

因此，正式实现前需要先确认：

- 内部界面是否保持在当前小关卡边界内。
- 内部界面是否只是编辑器管理视图。
- 导出时是否仍然生成同一个小关卡对应的场景结构。

## 可拆 issue

第一阶段先拆原型验证 issue，不直接拆正式实现。

建议 issue：

1. 设计小关卡内部弹窗管理的可点击原型。
2. 原型方案 A：小关卡内部界面节点。
3. 原型方案 B：小关卡内部页面列表。
4. 对比两种原型下老师完成弹窗编辑任务的路径。
5. 梳理第一阶段正式实现是否保持小关卡导出边界。

后续正式实现 issue 需要等原型结论出来后再拆。

## 验收标准

第一阶段原型验证完成的标准：

- 可以在原型中完成主界面、弹窗 A、弹窗 B 的切换。
- 可以看出按钮和弹窗之间的打开关系。
- 可以判断哪种方案更适合老师理解和操作。
- 可以明确是否保持“小关卡是导出边界”的原则。
- 可以据此拆出正式实现 issue。
