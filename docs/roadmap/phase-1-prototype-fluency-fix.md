# 阶段一原型：流畅性与交互修复清单

> 更新日期：2026-07-13  
> 用途：在正式方案选型前，先把三套原型修到“能公平比手感”的状态。  
> 范围：只改 `docs/roadmap/phase-1-prototypes/` 与相关说明文档，不改正式编辑器。  
> **实施状态：第 1 批 P0 已落地（2026-07-13）；左右栏可伸缩已补齐（2026-07-13），可开始手感复验。**

---

## 一、修复目标

当前原型业务主链路大体能跑，但存在一批**流畅性噪声**。它们会让老师误判成“方案不行”，而不是“布局差异”。

本轮修复目标：

1. 列表再长也能稳定滚动、看到底部内容。
2. 拖拽手感接近 PPT，不需要“猜怎么拖”。
3. 三套方案能力一致，只保留布局差异。
4. 首次进入就能直接体验内部页面管理，不绕路。
5. 修完后可以做一轮公平的方案体验对比。

**完成标准：** 按第九节验收路径走完三套方案时，不应再被滚动、遮挡、拖不起、入口找不到等问题打断。

| 级别 | 含义 | 处理策略 |

## 三、P0：流畅性硬伤（优先）

### P0-1 方案一左侧关卡列表滚不动 / 看不到下方小关卡 ✅ 已修

**现象**

- 新增多个小关卡，或展开多个内部页面后，下方内容看不到。
- 滚轮无反应，或只能滚一点点。
- 这是当前最直接的“交互不通畅”。

**根因（代码层）**

1. 方案一左侧用了：
   - `.left-stack { grid-template-rows: minmax(300px, 62%) minmax(170px, 38%); }`
   - 关卡区最小高度被锁在 300px，元素区最小 170px。
   - 窗口不够高时，整列被撑破，父级又是 `overflow: hidden`，结果不是“可滚动”，而是“被裁切”。
2. `.stage-card { overflow: hidden; }` 在内容变高时容易制造裁切错觉。
3. 拖拽过程频繁 `render()`，只按 `.scroll` 下标恢复 `scrollTop`；DOM 结构一变，滚动位置对错容器，表现为跳动或“滚回去了”。

**修复方向**

1. 左侧改为可收缩布局，例如：
   - `grid-template-rows: minmax(0, 1fr) minmax(140px, 32%);`
   - 去掉 `minmax(300px, …)` 这种硬下限。
2. 明确只有 `.stage-list.scroll` 负责滚动；`stage-card` 不再用会裁切内容的 `overflow: hidden`。
3. 新增 / 选中 / 展开小关卡后，自动 `scrollIntoView` 到当前项。
4. 滚动恢复改为按稳定 key（如 `stage-list` / `elements-list` / `drawer-views`）记录，不按下标猜。

**验收**

- 连续新增 6 个以上小关卡，仍能滚到最后一个。
- 同时展开 2 个内部页面树，仍能滚到最底部的“＋ 新增内部页面”。
- 选中最底部小关卡时，该项进入可视区。

### P0-2 拖拽启动门槛过高，经常拖不起来 ✅ 已修

**现象**

- 必须按住 ⠿ 长按约 180ms。
- 长按期间鼠标稍一移动（>7px）就取消。
- 老师习惯“按住就拖”，体感是拖拽坏了。

**修复方向**

1. 按住把手后允许立即进入“待拖拽”，移动超过阈值（约 4~6px）即开始拖，不再强制长按。
2. 长按仍可保留为辅助，但不作为唯一触发。
3. 拖拽中才屏蔽 click；普通点击把手不应误触菜单。
4. 后续可增强：按住整行空白区域也可拖（排除按钮热区）。

**验收**

- 按住把手直接拖，无需停顿等待。
- 轻微抖动不会取消。
- 点击把手或标题仍可正常选中，不误触发拖拽。

---

### P0-3 方案三跨关卡面板挡住本关页面列表 ✅ 已修

**现象**

- 专注模式下一拖页面，左侧固定浮层盖住页面导航。
- 本关内排序几乎做不了。
- 跨关卡目标也只能粗暴“丢进某关”。

**修复方向**

1. 跨关卡面板改为**附加区域**，不覆盖本关列表。推荐：
   - 放在画布上方横向条；或
   - 放在左侧列表下方独立分区；或
   - 放在右侧次级面板。
2. 本关内排序继续使用原页面列表的占位预览。
3. 跨关卡目标默认只显示“其他兼容小关卡”，不重复当前关。
4. 放置到其他关后，仍停留在目标关与被移动页面。

**验收**

- 专注模式下可完成本关内排序。
- 同时可把页面拖到其他兼容小关卡。
- 拖拽过程中本关列表始终可见、可瞄准落点。

---

### P0-4 拖拽时自动滚动弱 / 滚动位置乱跳 ✅ 已修

**现象**

- 列表较长时，拖到边缘不能稳定自动滚。
- 一出现放置预览就整页重绘，滚动位置跳动，目标丢失。

**根因**

- `updateDragTarget` 一变化就全量 `render()`。
- `autoScroll` 每次只改 12px，且重绘后目标检测不稳定。

**修复方向**

1. 拖拽中尽量局部更新：
   - 幽灵卡片位置
   - 高亮 / 占位符
   - 不要每次重置整个工作区 DOM
2. 若暂不能局部更新，至少：
   - 用稳定 key 恢复滚动
   - 拖拽态避免无意义重绘
3. 边缘自动滚动改为连续滚动（requestAnimationFrame），靠近顶部/底部时加速。

**验收**

- 长列表中可把页面从顶部拖到底部并成功放置。
- 拖拽过程中列表不乱跳。
- Esc 取消后列表位置保持合理。

---

### P0-5 首进路径不聚焦，体验像“空壳编辑器” ✅ 已修

**现象**

- 默认落在普通练习关。
- 内部界面小关卡还是占位，要再点创建才进入正题。
- 老师第一分钟不知道在对比什么。

**修复方向**

1. 三套方案默认直接带一份可体验样例数据：
   - 1 个普通关卡
   - 1 个已创建的内部界面小关卡
   - 内含：主界面 + 1 个同级页 + 1 个弹窗
   - “第 2 题”按钮已预配跳转到同级页
   - 另留 1 个未配置按钮，用于演示待处理，而不是一进来满屏报错
2. 默认选中该内部界面小关卡主界面。
3. 方案二默认打开抽屉；方案三可先停在工作台，但样例关卡上有清晰“专注编辑”入口。

**验收**

- 打开任一方案 HTML，3 秒内能看到内部页面结构。
- 不点“创建模板”也能试运行一次页面跳转。

## 四、P1：明显不顺，影响公平对比

### P1-1 方案二抽屉开关节奏不顺

**问题**

- 收起抽屉后，只点小关卡不会自动打开。
- 托管小关卡的内部页面入口容易丢。
- 横向四栏时画布偏挤。

**修复**

1. 选中“内部界面”小关卡时自动打开抽屉。
2. 选中普通/视频小关卡时，抽屉切到组件列表（可保持打开或轻量模式）。
3. 抽屉头部始终显示当前小关卡名与页面数。
4. 窄屏下允许抽屉覆盖式展开，避免把画布挤没。

---

### P1-2 跨关卡只能丢到末尾，做不到指定位置 ✅ 已修

**问题**

- 文档要求“放到目标小关卡内部指定位置”。
- 方案二/三跨关卡投放很多时候只是 append。

**修复**

1. 兼容目标展开后，支持在目标页列表的具体空隙落下。
2. 若目标未展开，先落入末尾，并 toast 提示“已移入，可继续排序”。
3. 三套方案同一套落点规则。

---

### P1-3 内容页 / 弹窗分组与真实顺序打架 ✅ 已修

**问题**

- UI 分成“内容页面 / 弹窗”两组。
- 底层 `viewOrder` 是扁平数组，拖拽可把弹窗插进内容页之间。

**修复（二选一，推荐 A）**

- **A. 分组约束：** 同级页只能在内容区分排序；弹窗只能在弹窗区分排序；跨组不可落。
- **B. 取消视觉硬分组：** 改成单一列表 + 类型标记。

原型阶段推荐 A，老师更好理解。

---

### P1-4 不兼容目标只变淡，不说明原因 ✅ 已修

**修复**

- 拖到不兼容小关卡时，行内或落点区直接显示：
  - “模板不同，不能移入”
  - “普通关卡不接收内部页面”
- 松手时 toast 再强调一次，不静默失败。

---

### P1-5 方案一密度失控

**问题**

- 多小关卡同时展开，左侧迅速挤爆。
- 上半关卡树、下半元素列表互相抢高度。

**修复**

1. 展开一个内部界面小关卡时，可选择自动折叠其他（默认开启，可先做简单版）。
2. 当前选中项始终保持可见。
3. 元素列表高度下限降低，优先保证关卡树可滚。
4. 折叠态显示页数与待处理数，避免信息丢失。

---

### P1-6 技术字段外露 / 待处理太像报错

**修复**

1. 列表不再显示 `templateId` 原文，改成“内部界面 / 普通 / 视频”。
2. 预置“第 2 题”若用于演示，应已配置目标；待处理样例单独放一个“提示按钮”。
3. 待处理文案保持自然语言，并带直接修复入口。

---

### P1-7 右侧“交互”页签弱

**问题**

- 方案一有「属性 / 交互」页签，但交互里常常只能看不能配。

**修复**

- 交互页签中直接提供“配置目标 / 修改目标 / 清除事件”。
- 或者先取消页签，统一放在属性里的“事件链接”，减少找入口成本。

---

### P1-8 弹窗在画布上的可编辑性不足

**问题**

- 选中弹窗后，画布只像预览层，标题/内容等不易点选。

**修复**

- 编辑态弹窗层渲染弹窗内可点组件。
- 底板来源变化后，用一句话标注“底板：当前小关卡主界面”。

---

### P1-9 撤销入口不稳定

**问题**

- 只有单步撤销。
- toast 消失后找不到撤销。

**修复**

1. 关键操作保留最近一次可撤销：移动页面、移动小关卡、复制、删除。
2. 顶栏增加“撤销”按钮，有可撤销态才高亮。
3. toast 仍可快捷撤销，但不作为唯一入口。

## 五、工作区伸缩与 P2

### 已补：左右栏可伸缩 ✅

三套方案共用：

1. 左侧栏（方案一 left-stack / 方案三导航 / 方案二关卡栏+抽屉）可拖分割条调节宽度。
2. 右侧属性栏也可拖，进一步放大画布。
3. 双击分割条恢复默认宽度。
4. 宽度按方案写入 `localStorage`（`forge-phase1-layout-*`），刷新保留。
5. 有最小/最大宽度，避免拖没或拖爆。

### P2：质感优化（可后置）

1. 全局字号过小（大量 7~9px），评审时费眼。
2. 试运行时左侧仍可随意切换，缺少轻量锁定。
3. 新建/重命名弹窗的键盘回车确认、Esc 关闭可再统一。
4. 拖拽幽灵卡片可显示“移动到：xxx / 第 n 位”。
5. 三套方案的空状态插画与引导文案可更统一。

## 八、本轮明确不改

1. 不改正式编辑器数据结构与导出。
2. 不在本轮锁定最终采用哪套布局。

## 九、修复后验收路径

三套方案分别执行：

1. 打开原型，确认默认已有可体验的内部界面小关卡。  
2. 连续新增 5 个小关卡，确认能滚到最底部。  
3. 在一个小关卡内新增 3 个同级页 + 2 个弹窗，确认列表可滚、可点。  
4. 按住把手直接拖动，完成本关内排序。  
5. 拖到列表边缘时能自动滚动并成功放置。  
6. 复制页面，确认副本出现在下方且进入可视区。  
7. 配置按钮跳转，试运行成功。  
8. 将同级页拖到另一兼容小关卡的指定位置。  
9. 将弹窗拖到另一兼容小关卡，确认底板文案更新。  
10. 拖到不兼容目标时，看到原因说明。  
11. 撤销一次移动。  
12. 方案二：切换小关卡时抽屉内容同步。  
13. 方案三：拖拽时本关列表不被遮挡，且能跨关移动。  
14. 确认三套只有布局不同，业务结果一致。

## 十一、当前结论

第 1 批 **P0 五项** 与影响选型的 **P1-2/3/4** 已落地，可以开始三套方案的手感复验。

本轮实际改动摘要：

1. 左侧关卡区改为可压缩 + 稳定滚动 key，新增/选中自动滚入可视区。  
2. 拖拽改为“按住移动即拖”，边缘连续自动滚。  
3. 方案三跨关卡目标改到左侧导航底部，不再遮挡本关列表。  
4. 默认样例：内部界面小关卡已创建，含主界面 / 第 2 题 / 提示弹窗，并预配跳转。  
5. 顶栏增加撤销；抽屉选中托管小关卡时自动打开；隐藏模板 ID 外露。  
6. 左右栏可拖拽伸缩，双击恢复默认，宽度按方案记忆。  
7. 跨关可落到目标关内具体位置；内容页/弹窗分区约束；不兼容原因在拖拽态与松手时明确提示。

**注意：** 若浏览器里还是旧数据，点一次「重新开始」或清掉 `localStorage` 的 `forge-phase1-*` 键（schema 已升到 v3）。面板宽度键为 `forge-phase1-layout-*`，与业务数据分开。

仍未修完的主要是 P1-7~9（交互页签/弹窗画布/撤销覆盖）与 P2 质感，不阻塞本轮布局对比。
