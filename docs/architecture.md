# forge 当前架构

forge 是面向豌豆思维课件制作的 Electron 桌面编辑器。React 负责编辑器界面和数据状态，LayaAir 与 `sdk_baiya` 负责课件组件渲染，Vite 开发服务器同时提供页面、资源代理和开发 API，Electron 负责用户电脑上的文件访问。

## 系统组成

```text
Electron 客户端（电脑 B）
├── 加载远程 Vite 页面
├── 本地课件目录与文件 IPC
├── 自定义模板目录
└── 发布产物写入
          │ HTTP / multipart
          ▼
Vite 开发服务器（电脑 A）
├── React 编辑器页面
├── /api/* 开发接口
├── preview-server 静态代理
├── 课件动态路由
└── 预览工程编译与上传
          │
          ▼
GameLoader + LayaAir + sdk_baiya
```

Vite 不是独立生产后端，`pnpm build` 只生成静态 SPA。forge 的常见运行方式是远程 Vite 配合 Electron 客户端，而不是把所有能力都放在同一台电脑。

## 主要入口

| 位置 | 职责 |
| --- | --- |
| `src/main.tsx` | React 启动入口 |
| `src/App.tsx` | 起始页、编辑器主布局、快捷键和本地自动保存 |
| `src/store/editorStore.ts` | 唯一全局课程状态、选中、剪贴板和 50 步历史 |
| `src/components/Canvas.tsx` | React 状态与 Laya 画布同步 |
| `src/utils/laya/core.ts` | Laya 启动、对象注册、预览模式和 sdk 运行上下文 |
| `src/elements/elementMeta.ts` | 组件类型、默认值、属性面板和导出元数据 |
| `src/utils/exportProject.ts` | 预览和发布课件工程的共享导出入口 |
| `vite.config.ts` | Vite 配置、静态代理、课件路由和 `/api/*` middleware |
| `electron/main.cjs` | Electron 窗口、远程服务器选择、本地文件和编译 IPC |
| `electron/preload.cjs` | 向渲染进程暴露受控 Electron API |

## 页面与状态模型

课程数据以 `Course` 为根，包含正常关卡、预习关卡、小关卡、内部页面、元素、动作和资源引用。

全局状态只存在于 `editorStore.ts`：

- 当前课程、关卡、小关卡和内部页面。
- 元素选择、复制粘贴、编组和画布变换。
- 页面缩略图、自定义模板和编辑历史。
- 页面、元素、动作和容器操作。

普通课件的预习与正课共享同一层级：一个大关卡是运行时的页面容器，包含一个或多个按顺序切换的小关卡；大关卡本身不额外生成可编辑页面。视频关卡仍是只含一个冻结视频小关卡的单页大关卡，不能继续添加小关卡。

复制小关卡时，副本插在原小关卡之后；复制大关卡时，副本插在原大关卡之后并包含其全部小关卡。两种复制都必须重建小关卡、内部页面、元素、动作、分组和引用 ID，不能让副本继续引用原关卡内容。作业和专题测评继续保持单页大关卡，复习课继续保持纯视频结构。

`App.tsx` 在课程状态变化后 15 秒写回 Electron 本机课程文件，并清理无引用图片；Ctrl+S 立即执行同一路径。localStorage 只保存少量界面偏好和旧兼容数据，不是课程状态的权威来源。

### 课件目录与另存事务

课件 ID 是发布身份，课件目录是当前编辑副本的本机位置。同一个课件 ID 可以存在于不同本机目录，但编辑器一次只登记一个活动路径；另存或重新打开后必须同步更新课程 JSON 路径、`forge-local://` 目录映射和按目录隔离的资源缓存。顶部课件身份区域持续展示活动目录线索，完整绝对路径只用于本机界面提示和打开文件夹，不进入课程数据、远程请求或 Git。

另存结果包含“目标副本写入成功”和“编辑器切换到目标副本”两个连续阶段。写盘事务成功后，新课程对象必须是与当前 Zustand/Immer 状态完全解除引用的可编辑副本，不能复用被冻结的关卡、页面或元素对象；活动路径登记、资源缓存刷新和当前课程切换全部完成后，界面才能提示另存成功。若目标副本已经写入但界面切换异常，必须明确告知副本已保存及其目标路径，不能误报为文件未写入，也不能声称仍在原路径继续编辑。

“另存为课件”复制的是可编辑课件源文件，不复制 `project/`、`esBuild/`、`.svn`、`.git` 或另存事务临时文件。源目录的版本管理信息不能带到新副本；目标目录已有的版本管理信息属于目标工作区，替换课件内容时必须保留。没有版本管理信息的新目录仍可本地编辑，发布资格由发布流程单独判断。

另存前必须在 Electron 主进程中解析源目录和目标目录的规范化真实路径，兼容 Windows 大小写、尾部分隔符与可解析的路径别名，并在任何写盘前阻止以下关系：

- 目标就是当前源目录。
- 目标位于源目录内部，避免递归复制自身。
- 源目录位于目标内部，避免替换目标时连同源课件一起删除。
- 目标 ID 对应的现有入口是指向其他位置的符号链接，避免替换越出用户选择的父目录和同卷事务边界。

目标不存在、为空或只包含目标自身版本管理信息时可以直接写入；目标包含结构有效且 ID 匹配的 forge 课件时，必须经用户二次确认后完整替换；其他非空目录不得覆盖。完整替换不能合并目录，而应在目标父目录内完成“异步复制到临时目录 → 写入并校验新课程 JSON → 保留目标版本管理信息 → 原目标改为备份 → 临时目录切换为目标 → 再次校验 → 删除备份”。事务标记与临时目录均位于目标父目录，普通错误、程序崩溃或断电恢复都优先保护原目标；大文件复制不得同步阻塞 Electron 主进程。

右侧属性面板的直接输入采用“实时状态 + 成组历史”的编辑事务：文本和有效数值在输入时立即写入 `editorStore.ts`，保证画布、缩略图和待保存课件使用同一份最新数据；空值、负号、小数点等未完成数值只保留在输入框草稿中。连续输入停止 500ms，或发生 Enter、失焦、切换对象/页面和保存时，只提交一条历史记录。保存入口必须先提交待结束的属性编辑事务，再从 store 读取最新课程，不能从输入框失焦推断数据是否已经生效。

页面缩略图是由当前 Laya 画布生成的编辑器派生状态，不进入课程内容模型。画布内容变化停止 500ms 后更新当前页面缩略图，连续操作会重新计时；切换页面、保存以及进入或返回预览时立即提交最后一次画面。截图失败只能保留诊断日志和既有缩略图，不能中断编辑或用空结果覆盖。

## 渲染模型

`index.html` 在 React 前同步加载 GameLoader 和 sdk_baiya，确保 `window.Laya` 与 `window.com.klzz.*` 在画布初始化时存在。

编辑模式和预览模式有意不同：

- 编辑模式使用占位组件规避 sdk 组件崩溃、自动播放和缩放动画干扰。
- 预览模式实例化真实 `layaType` 组件。
- React store 是数据源，Laya 对象负责画布显示和高频交互反馈。
- `elementMeta.ts` 同时驱动工具栏、属性面板、组件创建和导出，不应出现第二套组件定义。
- 只有稳定的课程 ID 变化才属于真实课件切换并触发课件级 Laya 清理；预习区、正课区和大关卡的折叠状态变化只影响左侧列表，不得清空当前画布。
- 页面全量重建以“课程 ID + 页面 ID”为渲染上下文，避免不同课程使用相同页面 ID 时残留旧画面；普通内容同步仍基于当前页面元素变化增量执行。

### 编辑器界面层级

- 画布网格、选框、标尺、辅助工具等局部浮层必须留在画布自身的层级范围内；可见、可操作的画布局部控件最高使用 `z-40`，不能越过全局模态层。
- 资源库、确认框、创建窗口等全局模态界面从 `z-50` 开始，并同时覆盖和阻断画布内容及画布局部控件。
- 全局模态内部确有二级确认界面时可以使用更高层级；不得通过单独提高某个画布控件层级解决局部遮挡。

## 远程文件边界

Electron 和 Vite 运行在不同电脑时，路径只对各自所在机器有意义。

- 课程根目录和 `outputDir` 属于 Electron 本机，不能发送给远程 Vite。
- 远程服务器需要的资源通过 HTTP 上传。
- Electron 本机副本通过 preload 暴露的 IPC 写入或复制。
- `forge-local://` 协议把课程 ID 映射到 Electron 本机目录，用于安全读取本地课程资源。
- 凭据、证书、本机课程和生成的预览内容都不进入 Git。

## 预览与导出

工具栏的预览和发布都进入 `exportProject.ts`，根据课程类型生成正课、作业、预习、专题测评或复习课工程。

主要过程：

1. 校验课程结构、动作目标和资源。
2. 编译内部页面和组件树。
3. 收集、去重并改写图片、音频、视频和骨骼资源。
4. 生成 Laya UI、脚本、配置、atlas 和版本映射。
5. 预览时上传编译结果并打开 GameLoader。
6. 发布时写入 Electron 本机课件目录，再进入项目既有提交链路。

详细过程见 [export-pipeline.md](./export-pipeline.md)。

## 模板与资源

项目存在两类模板：

- 内置预设：随代码维护，用于提供稳定的组合起点。
- 自定义模板：存放在用户选择的本地目录，按 MD5 去重并跨课程复用。

大型素材库 `public/builtin/library/` 默认不进入 Git。代码只维护资源使用规则和必要 runtime，素材版本需要由团队另行同步。新增 `public/builtin/runtime/game/` 文件后必须重新生成 `game.zip`。

## 验证体系

- `tests/` 使用 Node 测试执行器覆盖画布几何、选择交互、内部页面、模板/资源扫描和资源库检索等纯逻辑。
- `pnpm build` 同时执行 TypeScript 构建和 Vite 生产构建。
- Electron、本地文件、真实 Laya 渲染、预览和发布仍需要人工验收。
- `pnpm lint` 对 TypeScript、React Hooks 和项目规范执行全量静态检查。

验证范围见 [testing.md](./testing.md)。

## 已知边界与风险

- Vite 开发 API 没有独立生产服务边界，只应运行在受控开发网络。
- sdk_baiya 和 LayaAir 以全局脚本加载，初始化顺序是硬约束。
- 部分能力依赖未入库的素材库和本地课件环境，CI 无法覆盖真实资源完整性。
- Electron IPC、远程双机模式和最终 GameLoader 表现不能只用浏览器构建结果判断。
- lint、单元测试和静态构建可以在 CI 中覆盖代码层回归，但不能替代远程双机与真实课件验收。
