# 老师课件发布流程

本文定义老师在 forge 中把课件工程提交到 SVN 并通知现有打包机的完整流程。它只约束编辑器侧的确认、工程生成、SVN 同步、通知和状态展示，不改变打包机内部的编译、合并、上传、部署或反馈协议。

## 用户结果

老师从工具栏进入一个连续的发布窗口，依次完成：

1. 确认最新预览。
2. 确认 SVN 目标和本次影响。
3. 生成并校验完整工程。
4. 同步、提交 SVN 并取得 revision。
5. 通知现有打包机并查看当前可获得的反馈。

窗口不得把“工程生成成功”“SVN 已提交”或“通知已发送”混写成“发布成功”。只有 SVN commit 成功且 `integrationRequest` 已发送时显示“发布已提交”；收到现有打包机的“全部完成”反馈后才显示“发布成功”。连接中断或没有最终反馈时保留“发布已提交”，并引导老师查看打包机反馈群。

## 最新预览确认

发布范围按实际工程区分：

| 课件情况 | 必须确认的范围 | 对应工程 |
| --- | --- | --- |
| 普通课件含预习 | 预习、正课分别确认 | `Game1_PREVIEW`、`Game1_LT` |
| 普通课件不含预习 | 正课 | `Game1_LT` |
| 作业 | 作业 | `Game1_HW` |
| 专题测评 | 专题测评 | `Game1_HW` |
| 复习课 | 复习课 | `Game1_REVIEW` |

预览完成后，编辑器计算对应完整工程目录和课件内容的稳定 SHA-256 指纹。目录与文本指纹都必须由 Electron 本地进程计算，不能依赖远程 Vite 页面所在地址是否属于浏览器安全上下文；因此 Electron 连接 localhost 或另一台电脑提供的局域网 HTTP 地址时必须得到相同结果。老师在发布窗口勾选“我已确认内容无误”后，确认记录保存范围、工程指纹、确认时间和编辑器版本。正式发布重新生成工程并再次计算指纹；任一必需范围与确认记录不一致时停止，不进入 SVN。

目录指纹覆盖模板原有结构、生成源码、配置、场景、依赖和实际运行资源，因此课件内容、导出规则、工程模板或运行资源变化都会使受影响范围失效。预习工程和正课工程分别记录，只有共享生成结果同时变化时才同时失效。编辑器布局、面板开关等不进入工程的偏好不会影响确认。

确认记录保存在 Electron 用户数据目录，不写入老师持续编辑的课件 JSON，也不依赖远程 Vite 所在电脑的文件路径。关闭重开后，只要课件、生成结果和编辑器版本均未变化，记录继续有效。

## SVN 目标

部署端为每类课件提供只读基础地址：

| 课件类型 | 默认部署配置 |
| --- | --- |
| 正课、作业 | `svn://192.168.74.9/product/trunk/course/Math` |
| 专题测评 | `svn://192.168.74.9/product/trunk/course/Math/SPECIAL_EVALUATION/YZ` |
| 复习课 | `svn://192.168.74.9/product/trunk/course/Math/REVIEW/YZ` |

地址由 Vite 开发服务的发布配置接口提供，界面只读展示，不在 React 业务界面中写死。老师填写基础地址之后的业务父目录相对路径，并选择一个已经通过公司 SVN 客户端拉取的“本地 SVN 文件夹”；当前课件文件夹名由编辑器读取并只追加一次：

```text
<基础地址>/<业务父目录>/<当前课件文件夹名>/
```

业务父目录至少包含一级。输入会统一空格和斜杠，不接受协议、主机、盘符、绝对路径、`..`、空路径段或以当前课件文件夹名结尾的重复路径。最终 SVN 结构不得出现重复课件名、`project/` 或临时中转层。

本地 SVN 文件夹中尚不存在目标业务父目录时，发布窗口必须完整展示将创建的目录层级；只有老师在最终确认中选择继续后，准备阶段才在本地创建并标记为待提交。取消准备会恢复本次新增内容，远端不变。

业务阶段使用 S1-S10 表示；三年级示例使用 `V9/S6`，不在界面和示例中虚构“第一讲”。

```text
业务父目录：V9/S6
课件文件夹：s6_v9_02_YY
最终地址：<基础地址>/V9/S6/s6_v9_02_YY/
```

## 本地 SVN 文件夹、地址映射与凭据

课件源文件可以保存在桌面、个人课件目录，也可以由老师直接创建或另存到最终 SVN 课件目录。发布窗口中的“本地 SVN 文件夹”仅指老师已经通过 TortoiseSVN 等公司客户端拉取到电脑上的目录，用于定位本次待提交工程；界面不再用“SVN 工作副本”要求老师理解版本控制概念。

老师主动选择本地 SVN 文件夹后，编辑器只从本地工作副本元数据读取该目录记录的真实 SVN URL 和仓库根地址，不能根据磁盘盘符、文件夹名称或路径文本猜测，也不在发布前连接远程 SVN 探测地址、权限、目录或 revision。所选目录对应的 URL 可以位于课型基础地址之上、等于基础地址，或位于基础地址之下；但必须同时满足：

- 所选目录与课型基础地址属于同一个 SVN 仓库。
- 最终课件地址位于所选目录覆盖的 URL 范围内。
- 所选目录若已经对应基础地址下的某个子目录，只映射尚未覆盖的剩余相对路径，不能再次套入 `V9/S6` 等已有层级。
- 所选目录不能覆盖最终课件地址时，直接说明两边真实地址和不匹配原因，不能继续提交。

例如，本地目录真实 URL 已经是 `<基础地址>/V9`，业务父目录填写 `V9/S6` 时，本地目标应映射到 `<所选目录>/S6/s6_v9_02_YY`，不能生成 `<所选目录>/V9/S6/s6_v9_02_YY`。

映射完成后必须比较当前可编辑课件目录与最终本地发布目录：

- 两者完全相同：进入“原地发布”，不创建第二份课件目录，也不清空课件根目录。
- 两者完全分离：进入“同步发布”，把生成工程同步到最终 SVN 课件目录。
- 两者互相包含但不完全相同：阻止发布并明确显示路径重叠，避免覆盖课件源文件或 `project/<课件ID>` 中的生成工程。

Windows 路径比较不区分盘符和文件名大小写，并在现有路径上解析真实目录后判断，不能因斜杠、大小写或符号链接误判发布模式。

编辑器记住成功校验的课件目标与本地目录绑定，后续发布可以复用；老师仍可重新选择。发布时：

- 不自动扫描整台电脑，不自动创建第二套隐藏 SVN 目录，也不全量 checkout 任一课型基础目录。
- 同步发布只整理最终课件路径及创建它所必需的父目录，不对所选目录执行远程 update，也不处理其中的无关课件。
- 原地发布只整理根目录下的 `forge-publish.json` 和实际 `Game1_*`，不删除、revert、add 或 commit 课件 JSON、`images/`、`project/`、`esBuild/` 及其他源文件。
- 操作前检查本次受管发布文件没有老师尚未提交的本地修改；原地发布中源文件的其他修改不属于本次发布范围，不能因此阻止发布。
- 同步发布的 commit 范围是当前课件文件夹及必须创建的父目录链；原地发布的 commit 范围是身份文件与实际新增、更新、删除的 `Game1_*`，课件源文件不进入本次提交。
- 正确整理当前课件内的新增、修改和删除后，打开公司已有 TortoiseSVN 提交窗口。老师完成提交且本地检查确认当前课件范围干净后，再取得实际 revision 并通知现有打包机。

Windows 安装包内置固定版本、带完整运行依赖和许可证的 SVN CLI，并始终通过安装目录内的绝对路径调用，不依赖系统 `PATH`，也不要求 TortoiseSVN 额外安装命令行组件。内置 CLI 仅执行本地工作副本的 `info`、`status`、`add`、`delete` 和 `revert`，不得用它连接远程 SVN；开发环境可以回退使用系统 `svn` 以便本地测试。

真正的远程提交必须调用老师电脑已有的 `TortoiseProc.exe`，复用公司 TortoiseSVN 已具备的 SASL、账号、权限和用户确认窗口。forge 不提供也不保存账号密码。Windows 正式包找不到 TortoiseSVN 时阻止发布并提示安装或修复公司 SVN 客户端，不回退为 CLI 远程提交；内置 CLI 缺失或损坏则提示重新安装当前测试版或联系维护人员，不能提示老师移动课件。

## 发布身份与同步边界

同步发布创建的 SVN 课件目录只包含身份文件和实际需要的完整工程：

```text
<课件目录>/
├── forge-publish.json
├── Game1_LT/
└── Game1_PREVIEW/
```

不同课型也可能只有 `Game1_HW` 或 `Game1_REVIEW`。原地发布时，同一物理目录可以同时保留老师的可编辑课件文件；Forge 仍只 add、revert、commit 和核验身份文件与实际 `Game1_*`，不把课件 JSON、原始 `images/`、`project/` 中间层、`esBuild/`、日志或版本管理元数据纳入本次发布。

`forge-publish.json` 记录 schema 版本、课件 ID、课型、课件文件夹名、发布内容指纹、编辑器版本、模板与运行资源环境版本、工程列表、工程树指纹和生成时间。它位于课件目录根部，不进入任何 `Game1_*`，也不作为打包机工程 URL；实际提交时间和 revision 保存在最近一次发布记录中。

准备覆盖前只依据本地工作副本中已经存在的身份文件和工程结构检查：

- 身份一致：允许更新，固定沿用首次发布地址。
- 原地目录尚无身份文件和根级 `Game1_*`：识别为首次发布，不把其中的课件 JSON、`images/` 或 `project/` 误判为同名冲突。
- 身份不一致或无法读取：阻止覆盖，不提供强制发布。
- 旧目录没有身份文件：名称和工程结构兼容时显示历史接管确认；老师明确确认后才写入身份文件。
- 本地工程树与上次身份记录不一致：识别为工作副本中存在待处理内容并阻止静默覆盖。若远端另有更新，老师应先通过公司 SVN 客户端更新本地文件夹后再发布。

同步以本次生成的完整工程为准，正确处理新增、修改和删除。删除预习区后，旧 `Game1_PREVIEW` 必须从 SVN 删除。提交前校验待提交目录与生成目录的工程树指纹一致，并确认没有未纳管文件。

## 状态、取消与恢复

执行阶段固定为：校验确认、生成工程、准备本地 SVN 文件夹、同步与完整性校验、打开 TortoiseSVN 提交、提交后核验、通知打包机、展示反馈。

- 校验、生成和本地同步准备阶段允许取消，远端不变。
- 打开 TortoiseSVN 后由老师确认或取消提交；同步发布打开课件目录范围，原地发布只打开身份文件与受管 `Game1_*` 范围。编辑器等待窗口关闭，不把窗口关闭本身当作提交成功。
- 通知打包机成功后解除编辑锁；窗口可以继续展示反馈。
- 老师取消、提交失败或提交后本次受管发布文件仍有待提交内容时不通知打包机，并提示继续在 TortoiseSVN 处理或重新准备；原地发布中的源课件修改不参与该判断。
- 提交后从本地 `forge-publish.json` 和各 `Game1_*` 目录读取实际 revision 与 URL；只有身份、工程 URL 和工作副本状态全部通过才通知打包机。
- SVN commit 成功但通知失败时保存课件 ID、SVN 地址、revision、工程 URL 和内容指纹；重试只重新通知，不重复生成或提交。
- 上述待通知任务保存在 Electron 用户数据目录，客户端重启后仍可恢复。
- 课件内容变化后不得复用旧待通知任务，必须重新预览、生成并提交。

编辑器只保存最近一次发布记录和当前可恢复任务，不建设完整历史管理页面。窗口关闭后，前台使用非阻塞通知，后台使用系统通知；发布入口保留最近状态，直到老师查看。

## 验收边界

自动测试覆盖工程指纹、确认失效、路径规范化、本地目录真实 URL 映射、原地/同步发布识别、路径嵌套拒绝、原地发布源文件保护与提交范围、全程不执行远程 CLI 命令、工程清单、身份冲突、历史接管、删除同步、TortoiseSVN 取消与提交后状态核验、实际 URL/revision、状态机和仅重试通知。真实 Electron 验收还必须覆盖安装包内置 CLI、TortoiseSVN 定位、本地 SVN 文件夹位于基础地址上级/同级/下级的匹配与拒绝、课件直接保存在最终目录时不搬移即可原地发布、公司 SASL 环境中的真实 SVN 首次/更新/删除/取消/冲突/权限/登录失效，以及四类课件通过现有打包机的完整反馈。

构建或模拟 SVN 测试不能证明公司真实 SVN、现有打包机、最终课件加载或 Windows 安装环境已经通过。未完成这些外部验收时，PR 必须保留明确的验收缺口。
